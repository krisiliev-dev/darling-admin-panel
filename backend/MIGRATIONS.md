# admin.db migrations (Alembic)

The panel's `admin.db` (users, audit, staging tables) is defined by the SQLAlchemy models in
`app/models.py`. **Alembic** is the migration tool for real schema changes.

## Runtime (Alembic is now the source of truth)
At startup `db.create_db_and_tables()` runs `db._alembic_migrate()`:
- **fresh DB** (no tables) → `alembic upgrade head` builds the schema from the migrations;
- **existing DB from the old create_all path** (tables, but no `alembic_version`) → `alembic stamp
  head` adopts it in place (schema already matches the models, so nothing is altered);
- **already-versioned DB** → `alembic upgrade head` applies any new migrations.

If Alembic errors for any reason, it **falls back** to the old `create_all` + `_backfill_columns`
(idempotent) so a migration hiccup can never keep the panel from booting. `tests/test_migrations.py`
asserts the migration chain's schema equals the models' (drift guard).

## Make a change
```bash
cd backend
# 1. edit app/models.py
# 2. generate a migration from the model diff
alembic revision --autogenerate -m "short description"
# 3. review the generated file in migrations/versions/ (autogenerate is a draft, not gospel —
#    check column types, server_defaults, and any data backfill it can't infer)
# 4. apply it
alembic upgrade head
```

## Adopt on an existing DB (one time)
An `admin.db` created by `create_all` already has the baseline schema, so **stamp** it as current
instead of re-running the baseline:
```bash
alembic stamp head
```

## Notes
- `migrations/env.py` reads the DB URL from `Settings.admin_db_url` (strips `+aiosqlite` → sync driver
  for migrations) and uses `render_as_batch=True`, so SQLite ALTERs (drop/rename/retype) work via
  copy-and-move table rebuilds.
- baseline (`*_baseline_schema.py`) captures the original schema; later migrations chain from it
  (e.g. `*_add_oversell_weight_kg.py`).
- Migrations are excluded from ruff (autogenerated).
- `_backfill_columns` remains only as the boot-time fallback; Alembic is the normal path.
